# RainaDrama 與小說改編公開素材方法蒸餾

- 核對日期：2026-08-29
- 來源母集合：<https://www.youtube.com/@RainaDrama>
- 用途：Novel 閉端 AI、裝置後備、Drama OS、Novel Video Engine 與逐鏡交接包。

## 證據與使用邊界

- 僅使用使用者指定 YouTube 頁面的公開標題、描述、頻道資訊與章節欄位；沒有下載影片，也沒有擷取或保存逐字稿。
- 「公開描述直接支持」與「只能由標題推論」分開標示。後者只可作產品假設，不能寫成已驗證事實。
- 只蒸餾一般性的改編與製作方法，不複製來源台詞、角色、鏡頭排列、提示詞或辨識性風格。
- 觀看、收入、速度、零門檻等數字屬宣傳或社會證明，不是故事品質、可持續收益或 Novel 能力的證據。
- 頻道對授權、更新頻率與內容品質的說法是頻道自述，第三方作品仍必須另做權利與同意檢查。

## 可核實的方法

### 故事必須先於生成

公開描述較完整的編劇資料主張：先決定煽動事件、主角目標與動機，再以「目標 → 行動 → 結果」建立因果鏈並逐步升高衝突；長篇可用三幕比例規劃。這些方法應先形成 logline、大綱與場景，之後才轉為分鏡與影片提示。

Novel 的實作要求：

1. 先以一句話固定 `人物身分／欲望＋異常任務或煽動事件＋逐步揭露的真相／代價`。
2. 每個場景都要有目標、可演行動、阻力、結果及下一個新條件。
3. 移除某段若不影響後續，該段是重述或填充，不能拿世界設定或旁白補長度。
4. 每集先兌現一項承諾或讓代價落地，再建立由角色選擇造成的未解問題。

### 小說不是直接壓縮成旁白

「小說 → 短劇」應視為獨立改編流程。角色要保留欲望、阻力與可辨識狀態；對白要能推動行動或改變關係；情節要保留因果與轉折。原文敘述應轉成可拍的場景、對話、動作及聲音，而非把整章摘要塞進畫外音。

### 分段生產、逐關驗收

可重跑的流程為：

`題材／受眾 → logline／大綱 → 劇本 → 角色與場景資產 → 分鏡 → 圖像／動態 → 配音／音效 → 剪輯／後製 → 發布`

每一關都要有明確輸入、輸出與人工 QA。AI 適合產生候選、批次化與降低視覺試作成本；沒有資料支持「全自動就會有高品質成片」。

### 系列、角色與跨語言版本

- 系列先定義總集數、單集時長、人物狀態、每集事件與集末未解問題；模型和工具可以替換，Story Bible 與連戲帳本不能跟著換。
- 角色視覺要先鎖定臉、體型、妝髮、服裝、聲線與持有物，再批量生成鏡頭。
- 海外版本不只是翻譯：可在不改變故事因果與角色正史的前提下，分開處理字幕、本地化節奏、調色、音效重製與視覺包裝。

## 寫入 Novel 的規則

- 閉端 AI 與裝置後備都使用同一套因果、角色、連戲與 QC 契約；後備不能靠固定段落換名詞。
- Drama OS 先產生可核准的劇本與逐鏡導演包，影片供應商只執行核准鏡頭，不得自行改寫正史。
- 供應商失敗不會自動把內容改送另一家公司；更換供應商必須重新確認資料外流對象、條款與費用。
- 成功狀態只有在 MP4 已下載至私有儲存並驗證格式、大小、時長與雜湊後才能成立；暫時 URL 或 JSON 不算成片。
